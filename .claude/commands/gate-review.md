# TESTAHIL gate review — the human half of the unattended pipeline

`auto_refresh.py`'s materiality gate stops and opens a PR whenever a refit would change
something a reader sees. Those PRs are never auto-merged, by design — which means the queue
only moves when someone reads the evidence. This tick reads it.

Scope to `$ARGUMENTS` if given; otherwise take the oldest unreviewed PR first.

## What you are deciding

The gate fires on exactly five conditions. Establish which one, from the report itself:

1. an existing name's verdict category changed
2. a NEW name arrived already FAILING (usually a misfiled or bad file)
3. the published 90% cone moved >5%, measured on `width_cal × q95(t(ν))`
4. the market-level panel verdict changed
5. a panel carries a name with no raw CSV in the library

A new name by itself is NOT material — placing the file at `raw_ohlc/{MKT}/{TICKER}.csv` is
the human decision about what the series is.

## Verify independently — do not grade the report against itself

- Read the report in `engine/PENDING_REVIEW/`, newest first (`ls -t`). Alphabetical order
  once picked a stale report as a PR body for an unrelated failure.
- Re-read the live `market_profiles.py` on **both** the PR branch and `main` and compute the
  cone move yourself: `width_cal × q95(t(ν))`, not ν and width_cal separately. They trade
  off, so watching them individually both misses real changes and fires on noise.
- Check whether the trigger is a **data** change or a **fit** change. Cleaning alone once
  flipped Korea's tail (ν 6 → Gaussian) and two names' robust verdicts. A ν move with
  ΔlogL under ~1 and a cone move under 1% is statistically indistinguishable noise, not a
  regime change.
- For a verdict flip: is it ROBUST across bootstrap block sizes {2,3,4}? A block-dependent
  sign flip is BOUNDARY — recorded PARITY-flagged, never a silent proceed.
- For a FAILING new name: separate **mis-centring** from **over-coverage**. A name with
  cov80≈1.00 and a PIT near 0.5 is perfectly centred and merely too wide for its own vol —
  a different diagnosis, and the one `adaptive_width.py` was adopted for (EG-only,
  history-gated at 28 resolved windows, and dormant until a name clears it).
- Confirm the engine still imports on the PR head before recommending anything.

## Output

Post ONE comment on the PR: which gate condition fired, what you independently measured
(with the numbers), your read of data-vs-fit, and a recommendation — merge, hold, or
investigate — with the specific evidence that would settle a hold. Then say the same thing
in three or four sentences in chat.

**You never merge.** Nothing that changes what gets published merges without a human
clicking it, whether a human or a cron triggered the change. If nothing new is in the
queue, say "queue clean" and end the tick.
